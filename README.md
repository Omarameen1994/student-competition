# 🏆 منصة مسابقات الطلاب عن بُعد

منصة ويب تفاعلية لإدارة مسابقة مباشرة بين فرق من الطلاب: أسئلة مباشرة، Buzzer سريع،
نقاط للفريق وللطالب، قدرات خاصة للقائد، ثم بطولة خروج مغلوب تُنشأ تلقائيًا.

**التقنية:** Next.js 16 + React 19 + TypeScript + Tailwind CSS 4 + Supabase (PostgreSQL / Realtime / RLS)

---

| المرحلة | الحالة |

| Phase 1 — الأساس (قاعدة البيانات، المشرفون، الطلاب، الأكواد، الفرق، الصلاحيات) | ✅ |

## 2) التشغيل المحلي

### أ) إنشاء مشروع Supabase

1. أنشئ مشروعًا جديدًا على [supabase.com](https://supabase.com).
2. افتح **SQL Editor** ونفّذ محتوى الملف:

   ```
   supabase/migrations/0001_init.sql
   ```

   هذا ينشئ كل الجداول، والدوال الذرّية، وسياسات RLS، ويفعّل Realtime.

3. أنشئ حسابَي المشرفَين من **Authentication → Users → Add user**
   (فعّل *Auto Confirm User*)، ثم نفّذ `supabase/seed_supervisors.sql`
   بعد تعديل البريدين والاسمين فيه.

### ب) المفاتيح

انسخ `.env.example` إلى `.env.local` واملأه من **Project Settings → API**:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...
STUDENT_SESSION_SECRET=نص-عشوائي-طويل
```

> ⚠️ `SUPABASE_SERVICE_ROLE_KEY` لا يُستخدم إلا على الخادم، ولا يظهر في المتصفح أبدًا.

### ج) التشغيل

```bash
npm install
```

```bash
npm run dev
```

ثم افتح `http://localhost:3000`.

## 4) سيناريو البطولة

**قبل الموعد:**
بطولة جديدة → إضافة الطلاب (يولّد النظام الأكواد) → توزيع تلقائي على الفرق →
تحديد القادة → إضافة الأسئلة → ضبط الوقت والنقاط والقدرات.

**يوم البطولة:**
الطلاب يدخلون بالأكواد → المشرف يضغط **بدء البطولة** → **بدء السؤال** →
الطلاب يتنافسون على الـBuzzer → المشرف يرى أول ضاغط وزمنه بدقة ويقرأ إجابته →
**صحيحة / خاطئة** → النقاط والترتيب يتحدثان تلقائيًا → القدرات تُفتح عند بلوغ النقاط →
**إنهاء مرحلة الفرق** → **إنشاء شجرة المواجهات** → اعتماد الفائزين →
🏆 التتويج تلقائيًا.

## 5) قرارات الأمان المطبَّقة

- **الخادم هو المصدر الوحيد للحقيقة.** لا يحسب المتصفح نقاطًا ولا يقرر أول ضاغط.
- **وقت الـBuzzer يُسجَّل على الخادم** (`clock_timestamp()`)، فلا تؤثر اختلافات ساعات الأجهزة.
  الصفحات تعاير فارق الساعة عبر `/api/time` لعرض مؤقت موحّد فقط.
- **أول ضغطة تفوز فعليًا:** الدالة `press_buzzer` تقفل صف الجلسة (`FOR UPDATE`)،
  فتتسلسل كل الضغطات المتزامنة، ويمنع فهرس فريد تكرار ضغطة الطالب نفسه.
- **منع التنفيذ المزدوج من المشرفَين:** `judge_buzz` ترفض أي حكم ثانٍ على نفس الضغطة،
  فلو ضغط المشرفان "صحيحة" في اللحظة نفسها تُحتسب مرة واحدة فقط.
- **الأسئلة والإجابات الصحيحة محجوبة عن الطلاب:** جدول `questions` لا توجد له سياسة قراءة
  للطلاب إطلاقًا. ما يصل إليهم هو نسخة منقّاة في `competition_state.question_public`
  بلا الإجابة الصحيحة.
- **أكواد الدخول في جدول منفصل** (`student_credentials`) محجوب تمامًا عن الطلاب،
  بينما جدول `students` المقروء للترتيب لا يحتوي على أي كود.
- **كل كتابات الطالب تمر عبر `/api`** مع التحقق من الجلسة والصلاحية على الخادم،
  والقدرات لا تُنفَّذ إلا لقائد الفريق وبموافقة المشرف.
- **طرد جهاز فورًا:** زيادة `session_epoch` تُبطل جلسة الطالب في الحال.
- **كل شيء مسجّل** في جدول `events`، ولا يصل إليه الطالب.

## 6) النشر

**قاعدة البيانات:** Supabase (منفّذ بالفعل في الخطوة 2-أ).

**الموقع:** Vercel

1. ارفع المشروع إلى GitHub.
2. أنشئ مشروعًا في Vercel واربطه بالمستودع.
3. أضف نفس متغيرات البيئة الأربعة في **Settings → Environment Variables**.
4. اربط الدومين، مثلًا `competition.example.com`.

الطالب لا يحتاج إلى تثبيت أي شيء: هاتف + إنترنت + الرابط + الكود.

## 7) إذا كان الاتصال بـSupabase بطيئًا أو فاشلًا محليًا

على بعض الشبكات تكون عناوين Cloudflare التي يعيدها DNS لنطاق `*.supabase.co`
غير قابلة للوصول من Node تحديدًا (المتصفح يعمل بشكل طبيعي). العَرَض: كل طلب
يستغرق ~10 ثوانٍ ثم يفشل، وصفحات المشرف تعود إلى صفحة الدخول.

للتشخيص:

```bash
node -e "require('net').connect({host:'104.18.38.10',port:443}).on('connect',()=>console.log('OK')).on('error',e=>console.log(e.code)).setTimeout(6000,()=>console.log('TIMEOUT'))"
```

للحل، أضف في `.env.local` عنوان حافة Cloudflare يعمل من جهازك:

```
SUPABASE_EDGE_IP=104.16.0.1
```

يوجّه [dev-dns.ts](lib/dev-dns.ts) — عبر [instrumentation.ts](instrumentation.ts) — استعلام
DNS لهذا النطاق إلى ذلك العنوان. شبكة Cloudflare تعمل بـAnycast، فأي عقدة فيها تخدم
النطاق نفسه عبر SNI.

> هذا المتغيّر **لبيئة التطوير المحلية فقط**. لا تضِفه في Vercel — خوادمها تصل إلى
> Supabase بلا مشاكل، وتثبيت عنوان واحد هناك يضرّ بالأداء والموثوقية.

الحل الجذري هو معالجة سبب الحجب نفسه (جدار حماية، برنامج حماية يفحص TLS، أو المزوّد)،
أو استخدام VPN.

## 8) ملاحظات

- كل الأرقام والقواعد قابلة للتعديل من `/supervisor/[id]/settings` بدون تعديل الكود
  أو إعادة نشر الموقع: مدة السؤال، النقاط، عدد المحاولات، الخصم، عدد الفرق، طريقة القرعة،
  كسر التعادل، عرض الأسماء والنقاط، تفعيل الـBuzzer والأصوات، وجهاز واحد لكل كود.
- إعدادات القدرات (نقاط الفتح، عدد الاستخدامات، الحاجة لموافقة) في `/supervisor/[id]/powerups`،
  ويمكن إضافة قدرات جديدة كليًا.
- **الوضع التجريبي** في صفحة الإعدادات: ينشئ 10 طلاب و6 أسئلة تجريبية لتجربة كل شيء،
  ثم يحذفها بضغطة واحدة قبل البطولة الحقيقية.
- الأصوات مولَّدة داخل المتصفح (WebAudio) بلا ملفات خارجية، ويمكن كتمها من زر 🔊
  في لوحة الطالب أو تعطيلها من الإعدادات.
